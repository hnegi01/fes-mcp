# Curated tool surface for fes_mcp — hand-edit this file.
#
# One tool_id per line. To REMOVE a tool from the MCP surface, delete its
# line or comment it out with '#'. Tools not listed here are never exposed,
# so new SDK methods added by a registry refresh stay hidden until you add
# them. Override at runtime with FES_MCP_TOOLS.
#
# [write] tools are additionally gated: only exposed when
# FES_MCP_ALLOW_MUTATIONS=true, always carry destructiveHint, and ask the user
# for approval via MCP elicitation on clients that support it. Authorization
# itself is enforced by Sisense per user on every API call.
# [read, reclassified] marks tools the generated heuristic misflagged as
# writes; corrected after verifying the SDK source (registry.MUTATES_OVERRIDES).
# The migration module (dual-tenant) is excluded in code and not listed.
#
# CURATED from a full SDK duplicate-method review (2026-08-26 policy): every
# tool is exposed EXCEPT near-duplicates — where two methods hit the same
# endpoint or wrap each other, only the better one is uncommented, so an
# agent never chooses between near-identical tools. Each commented duplicate
# carries an [excluded: dup group N — reason] note; uncomment to re-expose.
#
# SDK-upgrade automation (scripts/03_reconcile.py, part of
# refresh_registry.sh) maintains two sections at the END of this file:
# DEPRECATED (ids the SDK removed — history, never uncomment) and STAGED
# (ids new in the registry, commented — delete one '#' to expose). It never
# touches listed/hidden/staged ids, so hand edits are safe.
# STAGED currently holds 1.1.0's new surface (report_manager, mergetool,
# get_groups, run_full_wellcheck, …) awaiting curation. SDK 2.0 collapsed the
# user/group family into canonical methods (get_users_all / get_groups /
# users_per_group(group_name=None)) — the retired variants are in DEPRECATED.
