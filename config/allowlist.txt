# Curated tool surface for fes_mcp — hand-edited.
#
# One tool_id per line. A line that is present and uncommented is ADVERTISED to
# MCP clients; commenting it out or deleting it removes the tool. Tools absent
# from this file are never exposed, so a registry refresh can add SDK methods
# without widening the surface. Enforced when the tool list is built AND again
# at dispatch, so a delisted tool is unreachable, not merely unlisted.
# Runtime override: FES_MCP_TOOLS.
#
# Organised READ first, then WRITE, and by module within each — a read tool
# cannot change anything, so the split is the fastest way to see what an
# untrusted prompt could reach.
#
# WRITE tools are additionally gated: they are only advertised when
# FES_MCP_ALLOW_MUTATIONS=true, always carry destructiveHint, and ask the user
# to approve via MCP elicitation on clients that support it. Authorization
# itself is always Sisense's: every call runs with the caller's own token.
#
# A disabled line carries its reason after an em dash — mostly near-duplicates,
# where two SDK methods hit the same endpoint or one wraps the other and only
# the better one is advertised, so an agent never picks between near-identical
# tools.
#
# Cross-environment modules (migration, mergetool) are excluded in code, not
# here: their SDK facades need a source AND a target credential, which this
# server's per-user session cannot express.
#
# New SDK methods and removals are filed into review sections at the end of
# this file by scripts/03_reconcile.py (part of ./refresh_registry.sh); triage
# them into the sections above.
